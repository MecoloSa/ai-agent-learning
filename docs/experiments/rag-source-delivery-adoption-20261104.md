# RAG来源交付落地与固定召回对照

日期：2026-11-04。用户确认上一轮RAG联动后实施。实际检索算法、embedding、重排、模型、确认权限和生产预算未调整。

## 实际结构

交互入口由程序设置structured_result=True，不暴露为模型工具参数，也不强制普通问答检索。模型自主生成queries；原工具完成召回与邻居扩展；format_documents在字符预算筛选后登记selected_sources；工具返回text/sources/omitted_blocks；原循环继续让模型生成答案；TurnSourceLedger在展示层列来源。默认False使首次分析/规划保留原文本协议，无命中/无有效查询等说明路径保留。预载和历史引用尚未迁移。

结构化不是模型生成新的JSON任务；JSON由Python工具生成。当前来源元数据仍随工具结果进入模型，且程序来源目录进入聊天历史，因此不承诺减少token。程序目录不写入confirmation_plan，来源位置也不等于逐句论断支持。

固定召回的三块文档：前两块为对应资料，第三块为无关长背景，900字符证据正文预算排除第三块。工具创建、参数校验、格式化、模型循环、正式状态保护和聊天归档均走实际代码。固定召回不测检索算法、embedding或重排效果与费用。资料目录用真实达到51200字节阈值的长文本触发RAG，不修改生产路由判断。

## 过程中的失败与保留

最初8个会话因合成资料太小，未满足真实RAG路由，未绑定检索工具；保留原记录，排除效果对照。这批8次模型调用消耗输入33868、输出1934 token，是本轮实验额外开销，不能隐去。实验辅助已加入调用前路由检查。

有效对照首个旧版会话完成后，报告序列化遇到set参数；原始observation和快照完整保留，修复序列化后仅恢复报告，不重新调用该会话模型。该会话总墙钟时间未知，比较统一使用原始记录的模型调用累计耗时。全部8个有效会话按原顺序完成。

缓存命中不同，不能将token变化直接换算账单涨幅，也不能把缓存变暖算成架构收益。未核实当前计费单价，不报告金额。生产embedding/重排调用逻辑不变，但本实验未调用它们，不能据此推算全RAG成本。

数据集回答仍有“测试集只能用一次”“无偏估计”等缺少适用条件的概括；核心任务符合不等于回答全面质量通过。质量阅读为助手人工记录，不是独立金标准。

## 结论与后续边界

采用收益是来源可追溯性及职责清晰，不是已证实的省钱或智能提升。暂时保留；下一步如优化成本，应先统计较长会话中来源字段与文末目录的重复占用，再比较程序保留来源、模型请求副本仅携带必要正文/定位字段的方案。不能为缩短上下文删除原文范围、截断提示或回查入口，不追加禁止重复引用的提示词。
