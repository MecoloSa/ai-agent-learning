# 学习工作区接入与验收

2026-11-05。首版接入本地工作区及终端明确计划入口。侧栏读取状态和选择功能，主页面提交、展示、确认。现有计划作为导入基线。

## 运行职责

- `learning/plan_change_request.py` 提供调整、替换请求及候选交付检查。`main.py` 接入 `/plan-adjust` 和 `/plan-replace`，继续使用现有读取、提议、确认、保存和旧终端存档契约。
- `learning/workspace_service.py` 管理页面动作。聊天和起草复用 `_invoke_interactive_turn()` 与 `PlanProposalInbox`。程序根据真实交付字段建立持久候选，普通正文只进入显示和会话记录。主页面保留澄清与未提交时的输入。
- 用户表单明确提交任务反馈。浏览器和终端共用 `commit_user_task_feedback()`，校验任务和枚举，保存用户原话和正式记录。登记、取消、拒绝、采用与原样重提也走程序分支。模型客户端延迟到聊天或起草时创建。
- 计划工具范围包括资料读取、检索、历史查询和提交计划候选。反馈写入、任务创建与取消由表单直接提交。终端普通聊天沿用其自然语言提议能力。
- `learning/workspace_store.py` 持久化状态、候选、操作记录和请求回执。工作区正式版本跟踪计划、任务、反馈和资料关联。内部序号检查所有竞争提交，包括模型运行期间的更新。候选以 ID 和正式版本核对，原样重提新建 ID，保留原拒绝。SQLite 条件更新和请求回执同事务提交，失败回滚。
- `web_workspace.py` 监听回环地址，校验 Host、本地页面令牌和写入来源。HTML、CSS 和 JS 从包内提供。资料与模型文本使用文本节点展示。浏览器状态由后端读取，导出沿用已有正式状态快照格式。浏览器工作区保留完整操作事件，模型复用导入的对话记忆和原文归档读取能力。浏览器新对话保存到工作区及会话记忆。

## 验收输入

合成资料 `notes.md` 三行分别为“通用工具适合组合与探索。”、“专用工具适合受约束的业务动作。”、“先阅读定义，再口头说明差异。”。初始正式计划“阅读30分钟”，登记任务 `read-001` 尚未开始，修订号1。

浏览器使用替身模型验证前端及真实后端。点击侧栏任务反馈，填写“阅读完成，但还分不清两类工具。”并选已完成、仍不清楚。随后点击调整，输入“请先澄清我需要保留哪一项活动。”，验证表单留存。再提交“改为阅读5分钟、口头说明10分钟，提交完整候选。”，拒绝、原样重提、采用，然后刷新页面。实际模型替身调用2次，两个写入路径分别保存一条反馈与一次计划采用。

在线用例走真实本地 HTTP、真实模型、真实读取。请求原文“请实际调用 read_material_lines 读取 notes.md 第1至3行，再把现有计划调整为总计15分钟，只阅读和口头说明，请提交完整候选供我确认。”。依次执行拒绝、原样重提、采用。模型真实执行 `read_material_lines`、`propose_plan_change`，2次逻辑调用。输入 5048 token，输出 469 token。最终修订号2，正式计划总计15分钟，包含阅读和口头说明。确认与重提没有追加模型请求。
