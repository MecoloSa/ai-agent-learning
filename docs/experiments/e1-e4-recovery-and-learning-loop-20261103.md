# E1—E4：空响应恢复、学习闭环与上下文实验

日期：2026-11-03。用户本轮授权直接修复空响应并推进E2—E4。没有修改系统提示词、模型配置、工具预算或框架。

## 一、已落地修改

### 1. 空响应有界恢复

位置：runtime/agents.py的_invoke_llm_once、_invoke_llm_raw、_aggregate_attempt_usage。
原流程：tenacity只重试网络错误；HTTP200但content空且无tool_calls时直接进入无效回答失败。
新流程：单一Retrying层，网络重试和空响应恢复共享原LLM_RETRY_ATTEMPTS总额度（当前3）。只对无正文、无正常/非法tool_calls、无refusal且finish_reason为stop/未提供的响应最多补发一次；length/content_filter/明确refusal不做该类恢复；连续两次空明确失败。相同消息不加纠错提示，不返回外层重跑工具。

多次尝试后usage_metadata表示逻辑调用累计已知用量，最终提供商原值保存在response_metadata.provider_usage_metadata，每次尝试保存在invocation_audit；任何一次用量未知则总量None，不把超时当0。失败异常也附带invocation_audit；交互审计收录该字段。没有扩大原有最坏尝试额度。

离线覆盖：瞬时空、持续空、工具请求、权限失败、网络/空响应交错、总额度1、原请求不变、工具不重复、refusal/length/content_filter不误重试等。

线上接线：复用2条历史请求，首个空响应由实验离线注入（零费用、明确标注），然后真实重发一次。一次成功；另一次真实响应也为空，按两次空保护终止。工具执行均0、消息完全一致。不能将此当自然故障恢复率，也不能把失败样本删除。产物recovery-online-acceptance-20261103。

仍然不是提供方内部根因修复；此前HTTP逐层诊断结论保留。

### 2. /feedback统一进入正式反馈历史

位置：learning/learning_commands.py。旧命令只调用apply_user_feedback更新任务latest_feedback，未写feedback_records；两条真实闭环都因此未通过正式记录检查。
修复：明确的命令授权不再索取额外确认，复用prepare_feedback_proposal/commit_feedback_proposal，原子更新任务与FeedbackRecord。没有另造一套反馈模型或写入路径。
既有快照不补造历史记录；未来命令写入同时具有任务状态和原话记录。普通命令、无效参数与取消任务限制均沿用原边界。

### 3. 工具阶段公开文本不能静默丢失

位置：main.py::_invoke_interactive_turn。原始恢复轨迹中，第一条含tool_calls的模型消息已写出计划/任务状态，最后一条仅补历史引用；旧代码只返回最后一条，用户实际没看到前半答案。
新交付收集公开content（不是reasoning_content），明确标“工具阶段的公开说明，非最终结论”和“最终回答”；最终已完整包含的片段不重复加入。候选/待确认操作及未满足执行要求不通过这条展示路径补造，旧候选标记和失实学习操作声明不重新引入；历史引用仍核验。完整展示结果同时进入原有记忆/归档，不让记录与实际展示脱节。
这是交付修复，不是要求模型重写或额外调用。取舍：过程文字与最终回答可能有部分语义重复，明确阶段以免将早期推断当最终事实。以后若要更细UI，需要独立事件展示，不能直接删公开答案。
原始真实响应序列冻结于tests/fixtures/evaluation/public_fragment_regression.json；离线回放证实原来缺失的阶段1、任务状态、原话均进入交付。

## 二、E2：两条真实学习闭环

入口tests/helpers/learning_closed_loop.py。技术资料：正常结束未再请求工具、不证明回答正确；保护性停止由程序预算/执行保护触发、不证明学习目标完成。非技术资料：叙述视角的信息范围、人物态度，以及藏信例句；不要求编程绘图。完整原文及脚本在manifest.json。

每条独立运行：真实分析和规划→/task登记read-001→/feedback明确已完成但self_reported_unclear→只讨论20分钟→候选n拒绝→再次候选y采用→新进程恢复及搜索/读取历史原话。

讨论原文：“今天最多20分钟，只阅读和口头说明。请依据已记录的困难讨论如何学习，只讨论，不修改计划、任务和反馈。”
候选原文：“请依据已有反馈调整后续学习计划，总计最多20分钟，只阅读和口头说明，保留学习目标和任务反馈，给出完整候选计划供我确认。”
恢复原文：“请复述当前生效计划及read-001的活动进度和理解反馈，并从来源1的历史中搜索‘今天最多20分钟’，读取命中的完整问答后逐字引用我的限制原话。不要修改任何计划、任务或反馈。”（实际输入使用中文双引号，见代码与产物。）

第一轮：两条控制路径完成，但feedback_records为空，不能记为全部通过。产物closed-loop-online-20261103。
反馈修复后复验复用首轮真实生成的初始分析/计划（initial-workflow.json记录reused_from，未重复付费生成），再运行全部交互和独立恢复。产物closed-loop-fixed-20261103。

| 范围 | 结果 |
|---|---|
| 技术控制链 | 拒绝状态不变；采用修订号只加1；任务和正式反馈保留；恢复状态与来源文件不变；原话逐字回查成功 |
| 非技术重试控制链 | 首次拒绝正确；再次请求只返回计划正文，没有提议工具调用，因此确认输入阶段不匹配，保留真实失败 |
| 非技术明确澄清补验 | 用户明确“上次拒绝、现在重新提交进入确认”，随后真实提交、y采用、独立恢复及历史回查通过 |
| 公开文本交付 | 技术恢复最初有答案丢段，已修复并冻结真实回放；最后两次真实独立恢复实际回答同时包含计划、任务状态和历史原话 |

非技术澄清原文：“我之前拒绝了上个候选。现在请重新提交一个候选计划进入确认流程，总计最多20分钟，只阅读和口头说明，目标和记录不变。”产物closed-loop-clarified-20261103；不是原始脚本一次通过。
最终仅恢复交付补验在closed-loop-delivery-20261103，均不修改业务状态或来源快照。技术计划5+10+5=20分钟，非技术10+10=20分钟，均为阅读和口头活动；理解仍是自报不清楚，没有自动变掌握。

质量限制：有些计划用未被结构解析器识别的阶段/表格布局，程序仅提醒、未强制模板；人工检查可执行和负荷。技术“模型主动决定”等措辞属教学简化，不能推断模型主观意图。非技术候选再次提交存在模型动作遗漏，未用更强提示词或自动解析正文冒充已提交来掩盖。

## 四、E4：大型结果外置候选，不启用默认

参考Deep Agents的原文外置/预览与回读（见架构参考文档S2）。只在tests中的RawReceiptStore和实验请求副本实现；原始完整历史仍保留。阈值2000字符仅实验变量，不是生产配置。

修正实验条件：两组都提供普通文件读取、按行读取、存储回读。模型自主选择，不强迫使用新增工具。10份资料结果：
