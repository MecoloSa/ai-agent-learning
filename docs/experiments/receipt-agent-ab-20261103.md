# 请求视图：正式工具循环对照（2026-11-03）

## 范围与方法

两例各按原始/整理/整理/原始运行，8条独立链。使用正式`analyse_materials_agentic`循环、完整生产分析提示词、真实绑定工具schema和真实文件；仅首批工具请求脚本化以统一起点，后续由模型决定。首批调用正常经过校验、去重、执行和预算，未请求模型。不评价首次工具选择能力，也不包含规划/交互端到端效果。

模型qwen3.7-plus、temperature=0.2，工具总预算12、模型轮数15（含脚本化首轮）；11次真实模型请求全部一次成功，无网络重试；15次真实工具执行，其中12次来自8批首批读取、3次为模型补读。源码和资料内容指纹均未变化。运行产物位于`.evaluation-results/receipt-agent-online-20261103/`。

## 输入

案例完整原文、两份源码及标记资料见`tests/fixtures/evaluation/receipt_agent_cases.json`与产物`inputs.json`。

- 截断：首批只取得“蓝签表示已阅读定义，不代表理解达标。”，truncated=true。后文真实规则是“橙签要求判断三个陌生例子，至少两个正确，并说明依据。”；允许继续读取后回答，未取得则应说明不足。
- 多来源：alpha.py变量为2、3，beta.py为5、8，均4行，返回required_count在前；要求每项对应文件名和行号。首批各请求1—200行，实际1—4行。

## 思考与下一步（未实施）

- 当前工具schema绑定后，三个需要补读且实际补读的链都成功执行有效读取；上一轮无schema时的猜测参数不能直接归因为业务工具契约缺陷。
- 整理回执仍保留truncated=true，但一次模型忽视了该信息。保留信息不等于模型可靠使用；不能凭一次失败证明格式因果，也不能宣布更多提示词即可修复。
- 候选：仅整理完整已知回执，截断/部分回执保留原始JSON。复用`stage_evidence`，分析和规划统一原则；先进行候选输入等价检查及4条截断链对照，再决定落地。不增加强制补读或模型自报置信度门禁。
- 当前日志“回答未包含资料引用”仅检测`[source=...]`正则，多来源整理组有语义清楚的表格引用，日志过度断言。候选改成“未检测到标准资料引用标记”，不扩写regex或将格式检查冒充语义评价。
