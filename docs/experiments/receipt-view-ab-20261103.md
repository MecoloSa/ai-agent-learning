# 读取回执表示：固定上下文在线对照（2026-11-03）

## 问题与范围

比较原始读取JSON与请求副本整理文本，是否影响模型利用相同证据。
不改业务源码；固定真实工具读取结果，使用短的共用实验系统规则；没有使用完整生产分析提示词，没有绑定工具，不评价完整Agent任务完成率。
案例原文、资料及预设调用见`tests/fixtures/evaluation/receipt_view_cases.json`。
输入和输出保存于`.evaluation-results/receipt-ab-online-20261103/`，仅发送合成资料。

## 方法

使用正式`build_agent_tools`生成读取结果；两组分别调用正式`prepare_model_messages`的无整理器和`stage_evidence`整理器分支。
每例独立初始化，原始/整理/整理/原始顺序，3例共12次真实生成。模型qwen3.7-plus，temperature=0.2；12次均一次invoke成功，无重试。源码指纹全部保持。
接口completed仅代表请求成功；人工检查正文、引用与工具请求，不把程序通过等同于语义通过。

## 质量判断与下一步

- 实际行范围：两组事实均正确，但整理组来源标注不完整，不能宣布质量无退化。
- 截断：主动请求补读可能合理。无schema环境仍产生工具请求，部分参数为字符串、包含不存在的offset/start_index，且一次请求不存在的search_learning_file。没有执行这些请求，不据此推断正式绑定工具时也失败。
- 失败后成功：已回答的3次均区分成功和失败，补充解释有所标注；整理组一次补充把视角称为“客观机制”，表述过于概括。另一次空响应原因未确认；初版记录未保存finish_reason，后续辅助代码已补记公开状态，不保存私有推理内容。
- 暂不扩展整理范围、不继续堆提示词、不立即删除历史。下一步使用真实绑定工具和生产分析循环，检查补读及多来源引用，保留两组同一起点。
