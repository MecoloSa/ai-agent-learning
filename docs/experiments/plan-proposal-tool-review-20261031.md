# 结构化计划候选工具方案与离线验证（2026-10-31）

## 必要性与范围

上一轮真实联合案例已正确回读20分钟及活动限制、正确使用当前反馈，却仅把候选放在普通代码块，未提交文本标记；没有正式确认/采用。用户同意继续按工具提交方向指导，本轮不再要求确认方向。

候选新增learning/plan_proposals.py的PlanProposalInbox，参数仅完整plan_markdown，StateModel拒绝未知状态/确认字段并去除首尾空白，strict字符串拒绝非文本。工具调用只保存本轮pending，复用update_learning_context纯函数做校验，不修改LearningState、不确认、不读写磁盘。标记由main注入，避免循环依赖/复制协议常量；空白、内嵌标记、未变化计划、重复提交均有检查。

main两处工具表同时接入，每轮start_turn清空旧pending；_invoke_interactive_turn新增可选plan_inbox，其他调用方兼容。批量结果全部回传后，成功候选直接进入finish_answer，无需额外模型复制。最终出口仅在显式执行要求满足时把工具候选变成程序内部标记，随后沿用历史引用展开。旧文本入口继续兼容。目标修改暂保留旧入口；工具候选与模型文本更新标记混用时拒绝，避免静默选一份。与反馈提议同时出现时保留内部计划标记，使既有外层混合操作保护统一拒绝两者，不能因隐藏标记误采用反馈。

execution_guard将propose_plan_change注册到ok/data成功判定；成功只指pending。原v/y/n、_review_context_change、保存、归档与恢复保持原实现，数据库/快照/CLI无迁移。原计划修改提示整段替换为更短工具契约，目标标记说明保留；不是在旧提示后叠加禁令。新工具描述有自身契约及schema，不把字数减少宣称为总Token下降或质量提升。

## 测试可见性与结果

新增tests/test_plan_proposals.py共16项，覆盖pending与状态分离，空白/非字符串/状态字段注入，四种标记拒绝，重复提交与轮次重置，工具/旧标记冲突，混合反馈冲突留给外层，以及同批回执完整、显式指定读取要求未满足时不能交付另一候选。

联合测试新增工具提交采用/拒绝两项：同上一轮完整历史和问题、3任务/1反馈。固定模型响应search→read→propose_plan_change，分别v/y与v/n，真实确认与保存、独立CLI新进程恢复均验证，原任务、反馈、目标、源文件保留，短引用在展示/确认前展开。另增两项混合反馈/计划调用顺序测试，模拟模型违背“不新增反馈”指令同时提出两种操作；两个工具均返回pending，但外层拒绝两者、无确认或状态变化。脚本预置v因此不匹配是反例的正确观察，不冒充成功采用。

更新提示词契约测试：模型不再被要求输出计划标记，目标标记仍唯一；旧计划入口兼容由真实确认回归继续验证，而非删除旧回归来制造通过。

候选只加载到内存，未写业务源码；上述新测试加原采用/恢复、引用、预算、执行保护、反馈和来源回归共157项通过，2条pytest已导入插件断言重写提示。早期155项后补2项实际混合调用回归，最终157项通过。当前业务未应用新模块/接口，新测试依赖候选，不能把157项写成正式源码成绩。没有候选在线实验，也没有宣称模型必然选择新工具。

## 落地顺序和限制

在聊天提供新文件全文及修改前后局部：新模块→成功注册→main导入/短提示→可选参数/最终出口/受控结束→会话初始化、绑定、每轮清理、派发参数。用户手动修改业务，tests直接完成。落地后先相关离线验证，再只跑一次联合在线采用；若工具未选择或无候选，保留失败，不猜测正文或抽样刷通过。

工具参数有效、回执pending、程序确认、落盘成功和内容质量分别观察。提交工具增加一次共享预算内工具请求，但本轮成功提交即结束生成，不新增裁判或强制重写；具体在线延迟和路由收益待验证。目标与新计划工具同轮混用的限制是第一阶段迁移取舍，不是永久能力目标。
