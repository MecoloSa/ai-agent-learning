# 文档结构工具的主智能体对照验收

三条独立提问分别在原工具集合与新增结构工具的集合上执行，随后针对短文失败补做一组复验。主模型沿用项目 CHAT_MODEL，结构模型使用 deepseek-v4.1-flash-1017。两组保留按行读取、文件清单和 PDF 读取。本次入口未启用 RAG，用合成文档隔离结构工具影响。

## 输入与运行

- short.md 为七行、三个主要章节。提问「请按文章顺序列出 short.md 的全部主要章节，并说明每章的关键事实。」
- long.md 为693行、四个主要章节，每章有「阅读练习」小节。提问「请完整概览 long.md，按主要章节顺序介绍内容，包括末章的结论。」
- 定点问题「short.md 里试验是哪天开始的？只回答日期和依据。」

核对事实为2026年3月12日、每组七个样本、雨天暂停记录、末章编号BLUE-3617。长文各章间用重复背景文字隔开，以检查后部事实是否被读取。材料结构规则，难度有限。模型自主决定工具顺序，两组交替先后执行。

入口为 tests.helpers.document_structure_compare，默认预检，--llm 执行在线请求，--case-id short 仅运行短文。输出目录必须为新目录。原始输入和结果在 .evaluation-results/structure-ab-20261111/，短文复验在 .evaluation-results/structure-ab-short-repeat/。

## 实际结果

| 案例 | 原工具集合 | 新增结构工具 |
| --- | --- | --- |
| 首轮短文 | 2次主模型调用，11.737秒，三节与事实正确 | 调用结构工具后，后续生成连续空响应，流程失败 |
| 长文 | 5次主模型调用，30.587秒，四章事实正确 | 8次主模型调用及1次结构模型调用，39.738秒，四章事实正确 |
| 定点查日期 | 2次主模型调用，4.550秒，日期及位置正确 | 2次主模型调用，5.334秒，直接按行读取，日期及位置正确 |
| 短文复验 | 3次主模型调用，11.678秒，三节事实正确 | 3次主模型调用，15.521秒，三节事实正确，包含一次空响应恢复 |

定点问题没有调用结构模型。短文通过结构工具取全文时，内部结构模型调用为0。长文结构工具返回四个主要章节，主模型随后读取正文。两组均覆盖到第693行并取得末章编号。

长文原组输入70315 token、输出1618 token。新组主模型输入86681、输出1710，内部结构模型输入2173，其输出另计。新组发生一次200至400行请求错误，修正为201至400行后继续。差异同时包含新增步骤、模型选择与参数纠正，不能全归因于结构识别。新增工具也增加未调用时的 schema 输入。失败调用的未完整记录用量不能按0计，缓存差异未换算费用。

结果由助手对照原文检查。此次没有证明整体质量或速度提升。保留主模型按需使用工具，后续用无目录、页码错位及真实长教材验证适用性，再决定缓存或结果精简。

## 暴露的问题与修复

预算耗尽及提交空章节时，inspection_complete 曾仅依据扫描范围变为true。两条新回归先复现失败，再将完成状态改为同时要求有效章节、页面扫描完成及可提取文字，并保留位置线索省略检查。最后一轮仍要求补读时结束并报告未完成，避免读取后没有剩余判断轮次。

修复后结构工具、网页状态与来源联动32项测试通过，3项既有依赖警告。本次未重复全量回归。此前全量及真实结构模型单独验收记录继续保留。
