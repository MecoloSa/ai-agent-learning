# 操作交付、正式状态与结构化读取来源落地

日期：2026-11-04。依据用户确认实施三项范围；不调用在线模型，不更改模型、预算、确认权限或持久化格式。

## 变更与原因

- 学习操作交付：真实pending生成待确认说明，请求过但无pending生成未成功说明；不靠继续扩充成功声明正则。普通查询不替换。失败后仍允许原循环修正参数。混合操作和伪造程序回执先检查，避免替换正文掩盖诊断。操作分支的模型正文可能被程序说明替换，原始响应留在审计，不是通用语义事实检查器。
- 正式状态：目标、当前计划、active视图字段进入每轮现取的current_learning_state；原任务、日期、版本、反馈、更正关系和字段说明保留。系统消息删除重复目标/计划。旧存档恢复时重建系统消息，无schema迁移。摘要过时提示改指向当前状态消息；prompt_history后续不再承诺保存完整旧计划。
- 读取来源：TurnSourceLedger独立于审计开关，从真实结构化回执收集按行、文件开头和PDF页级位置；错误不登记，重复去重、截断/partial/no_text保留。目录在确认正文确定后附加，不进入confirmation_plan。RAG拼接文本、预载证据、历史回读仍沿用原路径，未宣称来源全部迁移。

## 提示词归属

`_build_interactive_system_prompt`的docstring是维护说明，不自动发送；工具docstring可能通过工具schema发送，不能一概而论。实际交互规则用程序来源职责替换原PDF逐字复制要求；检索和预载引用规则保留。不添加迁移说明、预算算法或新案例答案。

## 离线验证

新增tests/test_priority_delivery.py：失败反馈后故意声称已记录、失败后参数修复、来源与确认正文分离、混合旧目标入口保护、来源去重及读取限制。用户输入为“请记录：今天最多20分钟，只阅读和口头说明。不要修改计划或任务。”，独立初始化，无正式反馈；故意错误current_context+task_id后，不修复时最终不得声称记录成功，修复时只产生pending。

首轮全量出现71项失败，逐类核对主要为旧系统布局、引用交付断言及实验适配器不兼容；迁移为唯一状态字段、原正文与程序附注分开断言，未放宽确认/保存/恢复、原始工具结果或失败不列来源的边界。后续读取失败分支的测试误要求来源目录，已修正，边界相关14项通过。最终全量结果以README和priority-adoption-verified-20261104.log为准。

测试辅助兼容新状态布局，但既有在线实验的旧baseline已经不再等同于历史生产版本；历史结果不改写，不使用新代码重跑结果冒充原对照。
