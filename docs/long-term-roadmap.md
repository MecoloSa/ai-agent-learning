# 项目长期完善路线：有依据、可持续跟进的学习助手

> 更新日期：2026-10-20。面向2027年Agent工程相关实习。
> 以代码、测试和README为准，按验收推进，不为框架数量重写。

## 1. 定位与下一步

面向MD、PDF、TXT、PY等本地资料，提供有依据的问答与计划，根据确认反馈持续跟进学习。

主线：资料与目标 → 计划 → 自然反馈 → 必要调整 → 确认 → 保存与继续。

**下一步：普通聊天中的受控反馈记录。** 不要求用户掌握命令，不先扩充分类或固定策略。实施顺序见[短期计划](short-term-roadmap-one-week.md)。

最小提议契约已由用户验收；工具接线、确认记录、上下文及v5存档方案待应用与在线验收。之后补自然语言创建任务，再按明确语义支持完成/取消；复用确认和保存边界，不把任务登记等同于Markdown计划修改，不让模型自行宣布用户已掌握。

## 2. 当前基线

- 工具已有结果回传、错误处理、预算和重复保护。
- RAG已有增量索引、可选混合召回、聊天重排和引用检查。
- full/window/summary与学习状态分别保存，可恢复原策略继续问答。
- current存档、历史快照及列表已验收，恢复来源不覆盖。
- 计划已有完整候选、确认/取消、修订号及任务待核对标记。
- LangGraph已有三节点、轨迹、检查点及受限失败恢复。
- 已有离线、检索、交互及Judge校准等评测入口。

缺口：自然聊天提议记录、会话级约束、历史反馈检索与纠错。快照恢复不等于完整长期记忆。

## 3. 近期：自然反馈与可靠调整

### A. 恢复能力收尾

保留回归，不扩建存档。实际失败、兼容问题或新需求才触发修改。

### B. 受控记录（待实施，当前优先）

- 主问答模型按需提议；程序校验、确认、提交和保存。
- 原话来源可追溯，任务/会话范围分开，状态字段可选。
- 区分聊天历史、正式反馈和有效状态。
- 对象不明先澄清，不擅自登记，不把临时约束变成永久偏好。
- 正式记录与状态变化简短合并确认；改计划仍走原协议。
- 如实返回待确认、已执行、拒绝或失败，限制重复与循环。

验收正常反馈、时间约束、假设/引语、模糊对象、取消、重复及保存失败。观察误记、漏记、确认打扰与成本。

不增加每轮分类模型或专用记忆Agent。保留/report、/feedback，并统一无状态更新时的语义。

### C. 反馈驱动调整

先观察真实表现，再针对重复失败改进。核对任务、授权、时间及已完成安排；候选经确认才采用。

不按类别套固定动作，不强制局部字符串编辑。FEEDBACK_ADAPTATION_RULES整段提案已撤回，候选测试不算线上验收。

## 4. 中期：可查询、可纠错的长期记忆

目标是找回本轮有用的信息，而非注入全部聊天。

| 信息 | 处理方式 |
| --- | --- |
| 当前目标、计划、进度 | 结构化状态，精确读取 |
| 困难、偏好、约束、调整理由 | 带来源、时间和范围的记录 |
| 资料正文 | 独立索引，不混入用户事实 |
| 近期对话 | 原历史或摘要，不作为状态唯一来源 |

顺序：

1. 记录已确认信息，支持任务或学习安排范围。
2. 先按任务、会话、时间查询，再按需增加语义检索。
3. 处理更新、冲突与过期，保留来源。
4. 支持纠错、删除和多目标隔离。
5. 按预算组织状态、相关历史、资料和近期对话。

“今天20分钟”有时效；自报理解不等于客观掌握。模型归纳与用户事实分开。

JSON/SQLite可作早期存储。后台写入、新框架或记忆Agent须由收益决定。

验收跨会话查询、更新、过期、纠错/删除及无记录拒答，与快照基线比较有用性和成本。

## 5. 后续：小而完整的MCP实践

- 将一两个只读工具封装为本地Server，复用业务实现。
- Client完成发现、schema、调用、错误回传和生命周期管理。
- 保留本地Function Calling对照、目录权限和调用预算。

验收业务结果等价，以及非法参数、越界、服务不可用。能解释协议成本，不宣称MCP自动提升质量。

## 6. 工程收敛与有条件的多Agent

按实际耦合整理交互、状态、确认、资料和编排。补齐配置、演示、测试命令与局限，不整体重写。

仅在独立核验、权限/上下文隔离或并行收益明确时接入多Agent。先做小对照，收益不足不并入。理解Supervisor、Hierarchical、Swarm，不以节点数代替协作能力。

## 7. 评测与优先级纪律

- 单测测边界，离线测控制流，在线测接线，人工核对语义。
- 区分工具成功、引用存在、结论受支持和学习效果。
- 记录质量、状态一致性、调用/token/延迟，保留基线与开关。
- 复用评测入口，一次改变一个因素，阶段通过后收尾。
- RAG和LangGraph仅因实际问题继续改；状态快照与检查点不能互相替代。

暂缓：无目标检索实验、存档扩建、分类/策略大全、建议Agent、后台记忆服务、通用自主写状态、复杂多Agent及微调。

**大改前必答：需求、缺口、复用、最小改动、关联风险/成本、验收与停止。** 方向变化同步规划，不把候选通过写成已落地。
