# 长期计划：形成有工程证据的学习Agent作品

更新：2026-11-03。面向2027年Agent工程实习，以验收里程碑推进，时间为建议窗口。前版保留在reference/long-term-roadmap-before-20261103.md。

## 当前架构候选与采用门槛

详细来源、原理、已验证范围与暂缓项统一维护于[架构借鉴清单与实验路线](architecture-reference-and-experiment-route.md)。这里保留长期里程碑，不将候选等同已实现。

1. **证据层与请求视图分离**：现已有完整记录/副本边界。下一阶段可将大原始回执内容寻址保存，请求保留定位、实际来源、范围及明确的预览状态；模型需要时回读原文。存储原型已验证10/10精确回读，不代表Agent已经具备该能力。采用前需完成权限/会话隔离、有效期、检查点恢复、引用支持及真实模型回读验收。
2. **按实际压力管理上下文**：先观察实际usage与完整请求，不因若干轮对话就清空工具历史。借鉴Pi/OpenHands的近期保留和独立压缩视图，结合本项目现有summary及历史回查；投影或工具schema变更时不能继续信任旧usage。大资料/长会话对照显示收益后再启用。
3. **统一资源适配，保留模型自主性**：分析和交互逐步共用列举、分页、读取、检索的契约与目录边界，不强制list→search→read，不用过多规则替代工具可用性。先双入口契约兼容与成本对照，再迁移；无需先迁移Agent框架。
4. **恢复生成与执行分开**：网络异常、空最终响应、工具失败、内容不支持分别记录；空响应有界恢复已获授权并落地，共享原尝试总额度、不重做工具，持续空仍失败。后续重点是留出验收和实际额外成本，不扩大默认重试。

参考实现与实验边界见[2026-11-03探索](experiments/autonomy-and-context-exploration-20261103.md)。这些是项目演进候选，不宣称新的通用研究方法，也不以接入更多模型/Agent数量证明先进。

## 阶段一：可信质量基线（未来1—2周）

完成短期计划，区分工具执行、内容质量与状态安全。统一已有评测的入口说明和报告结构，保留开发/留出边界、真实输入、条件指纹和人工判据。不以单次成功代替可靠性。

产出：完整学习任务演示、失败分类、基线报告及一个有证据的改进。优先于增加框架与模型。

## 阶段二：针对错误提升证据与记忆（2—6周）

依据失败选择RAG或记忆方向。RAG检查召回、原文读取、结论支持之间的损失；历史记忆检查更正、时间适用范围和原话回查。已有BM25、专用embedding、混合和重排基础，不重复建设同类模块。

只有对照显示收益才变更默认策略。记录资料/索引版本、缓存、回退和实际成本，按真实需求逐步明确记忆删除、失效、撤回语义。

产出：不依赖固定措辞的任务，解释策略适用输入及何时查不到，保留基线和回退开关。

## 阶段三：必要的交互工程整理（1—2个月）

质量基线暴露维护或恢复问题后，再从main.py分离交互执行、确认和审计适配，保持工具契约。先定义状态转换及持久化边界，再决定是否迁移某个交互子流程到LangGraph。初始三节点和失败规划续跑保留为对照。

重点验证确认幂等、异常中断、重复输入、恢复后的状态权威和历史证据范围。完整交互事务恢复属于新增能力，不能因已有checkpointer就宣称完成。

产出：一个有业务收益的恢复或维护改进与迁移前后验证，不是全量重写。

## 阶段四：实习展示与可复现交付（2—3个月）

准备5分钟演示、结构图、安装步骤、脱敏样例和评测报告。讲清工具选择/回传、RAG各阶段、摘要与原文、MCP边界、图状态与业务状态，以及一次失败驱动的设计取舍。

按实际环境完善依赖版本、错误诊断与最小CI。公开合成演示数据需标注，不提交私密资料、密钥或存档。

## 按需而非必做

多Agent：仅在独立核验或角色分工对质量有可测收益时试点，比较额外延迟和费用。不把两阶段处理改名为完整多Agent系统。

服务化/多用户：有实际需求后再设计身份、隔离和后台任务。目前优先保证单用户闭环可理解、可恢复、可验证。

长期记忆向量化：已有可选语义历史能力，后续重点是更新、范围和召回质量，而不是再加一个向量库。
