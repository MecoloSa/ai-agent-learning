# 项目重新评估：从机制建设转向完整任务质量

日期：2026-10-31。目标：有资料依据的学习助手，以及2027年Agent工程实习。结论依据当前源码、全量离线回归、已有实验报告与教材相关章节；本轮没有新增在线模型效果实验。

## 当前判断

项目已超出简单聊天机器人或RAG演示，具备工具执行、反馈确认、状态持久化、原文回查、可选编排和较丰富评测。当前最大差距是：这些机制的证据分散，尚需用少量固定完整任务说明它们共同带来了什么用户价值，以及在哪些输入下仍失败。

1585项离线测试通过说明控制和接口回归有基础，不等于回答正确率或学习效果。已有在线实验也不能因completed或conditions_unchanged就认定内容达标；质量/证据项pending必须继续作为未知。

## 最高优先级：完整学习闭环验收

例如：用户提供阅读资料，希望区分两个概念；阅读完成但仍不理解，今天时间更少且只愿阅读/口述。助手应检索并核对资料，区分完成和理解，讨论可行安排，提交候选；拒绝时不写，确认后保留任务与反馈。保存后由新进程恢复，当前计划一致，查原话时能够回读而不把摘要当引文。

这里分别检查最终内容、工具路径和状态变化，允许不同合理路径。自动校验保护边界，人工判断资料支持及活动针对性。复用现有feedback_plan评测和恢复测试，不另建一套框架。

先盘点已有输入与结果、固定缺口，再做少量必要在线补测。对可重复失败只选最重要的一类改进，保留基线并用独立任务验证。没有稳定失败时不继续改提示词。

## 次优先级与暂缓项

次优先级是维护与恢复边界：main.py和agents.py职责较集中，后续可在有验收保护后拆分交互执行与确认适配；只有真实中断案例需要时再扩展图编排。首次分析文本预算已独立，但不覆盖文件加载内存或此前检索开销；大目录资源问题需要单独测量，不能把120000字符解释成所有资源都安全。

暂缓全面框架迁移、多Agent堆叠、继续收紧提示词、服务化和无失败依据的默认检索策略更换。它们可能增加复杂度，却不能直接解决当前内容质量证据分散的问题。
