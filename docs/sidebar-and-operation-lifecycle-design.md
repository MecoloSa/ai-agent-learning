# 学习状态侧栏与统一操作入口

记录日期：2026-11-05。用户确认侧栏负责状态和功能选择，主页面承接填写、结果与确认。首版已实现，以下保留设计依据及后续关联升级边界。实现与验证见[工作区接入记录](experiments/local-workspace-integration-20261105.md)。

## 数据与展示

侧栏读取正式状态，展示目标、计划修订号、登记任务进度、自报理解和待确认数量，可直接展开正式计划正文。点击功能或任务只在主页面打开相应操作区并带入操作类型和任务ID。用户在主页面填写要求或反馈、提交、查看结果与差异并确认。窄屏常驻目标和进度摘要，按需展开计划和任务，腾出空间阅读对话。左栏提供工作区视图、记录筛选和状态导出。导航和记录检索参考 [ChatGPT Projects](https://help.openai.com/en/articles/10169521-projects-in-chatgpt) 与 [ChatGPT 记录搜索](https://help.openai.com/en/articles/10056348-finding-your-chats-projects-and-files-in-chatgpt)。

工作区以结构化任务变更连接计划候选和任务清单。Markdown 提供计划说明，任务行提供标题、估时、说明和当前进度。采用时在同一事务应用正文与任务差异；现有任务通过 task_id 定位并保留反馈。旧计划可单独提取，细化时保留原任务历史并分配新任务 ID。任务进度、自报理解、取消情况和最近反馈分开显示；完成比例统计未取消任务。

## 权限

用户直接提交进度和反馈是明确授权，复用/feedback正式提交，不让模型再次分类；模型只能提出待确认建议。目标/计划替换及取消任务先预览确认。创建任务由程序生成ID。恢复已取消任务使用专门操作，保留原进度。首版不开放任意历史原文覆盖或标题编辑，更正新增记录并关联旧记录。ID、版本、时间、确认结论和保存结果由程序生成，模型与资料不能赋予写入权限。

界面提供受控 JSON 入口。任务通过界面选择，允许编辑反馈正文、活动进度和自报理解，并复用反馈保存逻辑。计划手动编辑复用候选正文校验，经用户确认后采用。两类提交都走统一的版本和事务校验，无需调用模型。原导入快照保留，导出的 JSON 对应当前正式状态。

## 候选生命周期

候选保存ID、完整内容、变更范围、基于的状态版本、来源、待确认/已采用/已拒绝/失效状态及真实结果。拒绝保留历史。用户在主页面重新提交原方案时创建新候选，修改内容时生成新版本。侧栏显示候选状态摘要并导航到主页面中的真实候选卡。

## 一致性与保存

建立不依赖input/print的应用服务，CLI、工具、UI作为适配器；复用现有反馈、任务、计划状态函数。统一校验、提交、保存和返回最新状态。界面明确提交中/已保存/失败，保存成功后更新正式视图，失败保留编辑草稿。

context_revision只表示目标/计划版本，不能用于所有任务反馈并发。未来增加全状态版本，提交时核对读取版本，冲突不静默覆盖；请求ID防止重复点击/重试重复写入。版本检查与提交保存应在同一受控写入边界内，不能只由前端检查。模型基于旧状态的候选须重新核对。

## 实施顺序

1. 固定拒绝后漏提交请求先诊断，不能直接归因于提示词。
2. 给出共同命令、候选生命周期和保存契约，再按两阶段约定落实。
3. 接入侧栏状态视图与功能导航。主页面承接直接反馈、候选差异、采用、拒绝和重新提交。
4. 计划活动关联作为后续schema升级，单独评估兼容与迁移。

验收：聊天/UI一致、拒绝无写入、失败不报成功、旧版本冲突、重复提交幂等、取消保留历史、恢复后候选与正式计划分离。框架及多用户服务选型尚未决定，当前优先单用户闭环。

## 首版操作契约

自然聊天继续支持讨论与提出变更。确定性入口区分局部调整和整份替换。两者均以当前正式计划为基准，整份替换在新候选采用前继续使用旧计划。停止当前计划单列为未来操作。

终端先用`/plan-adjust 要求`和`/plan-replace 要求`验收。侧栏按钮在主页面打开相应模式的输入区，用户提交后才构造同一请求并运行工具循环。请求授权起草，读资料与历史、询问缺失条件、提交完整候选沿用现有流程。主页面根据程序结果展示待确认候选或未提交说明，澄清问题留在同一操作上下文中，用户确认后才采用。

先验收计划变更请求和交付结果，再设计主页面操作卡和侧栏导航。主页面保留完整候选预览，差异由程序比较正文。用户反馈表单由侧栏任务导航打开并绑定任务ID，明确提交后复用正式反馈逻辑。引入持久候选ID后开放按ID重新提交原方案和并发编辑。

终端目前区分会话内生效和磁盘保存。主页面的正式提交接口返回处理与保存结果，侧栏按返回的正式状态刷新。若要求保存失败即不生效，须先落实原子持久化再接界面写入。并发控制使用全状态版本或等价的比较并写入机制，计划修订号继续只表示目标和计划变化。
