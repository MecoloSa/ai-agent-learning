## 1. 本周主线

自然对话 → 受控记录反馈 → 必要调整 → 用户确认 → 保存并继续学习。

**下一步：普通聊天中的反馈记录提议。** 不再优先扩建存档、分类或固定策略提示词。

## 3. 第一优先：受控自然反馈（待实施）

### 数据边界

- 保留原话；进度、理解只是可选字段，不是全部反馈类别。
- 区分聊天历史、正式反馈、有效任务/计划状态。
- 反馈可属于任务或当前学习安排。“今天20分钟”不是永久偏好。
- /report、/feedback保留，不要求普通用户掌握命令与任务ID。

### 修改顺序

进度：用户已验收feedback_proposals契约及离线测试。本轮接线方案待应用：收件箱复用主问答工具循环，确认后统一更新任务及带来源记录，v5兼容读取旧快照；每轮一个有效提议、共享原预算。同轮反馈与计划候选不合并授权。current_context默认仅记录当天及同一计划版本主动使用，确认时明示，不是自动识别任意时间范围。业务源码未直接写回，内存候选关联241项通过，真实在线仍待验收。

此后先完成这条记录链路验收，再接自然语言创建任务，随后区分完成与取消；不把登记任务等同于修改Markdown计划，不先搭通用操作框架。

1. 定义最小记录：可信原话/消息引用、适用范围、可选任务与状态。
2. 主问答模型按需调用提议工具，只生成候选，不直接写状态。
3. 程序校验来源、对象与字段；对象不明先澄清，不擅自登记任务。
4. 简短确认后提交保存；取消、重复或失败不得误报成功。
5. 验证下一轮及恢复后可用，再推进计划调整。

同时统一命令语义：/report拒绝两个状态均为null的反馈，/feedback却允许只存原话。无状态更新不等于反馈无价值；格式错误仍应拒绝。

### 验收与停止

- 覆盖进度、困难、仅时间约束；未提及字段保持原值。
- 假设、他人引语不误记；模糊对象先澄清。
- 确认前不提交，取消/失败不污染有效状态。
- 来源与范围可追溯；记录反馈不授权改计划。
- 检查误记、漏记、确认打扰和调用/token/延迟。主要边界通过后收尾。

## 4. 第二优先：必要的计划调整

- 基于原话和请求生成候选，不按类别套固定学习动作。
- 保留完整计划与确认协议，不先做字符串局部替换。
- 核对授权、已完成安排、时间约束和任务对应。
- 仅针对可复现失败补规则；读完不等于掌握，不强制代码实践。

整段FEEDBACK_ADAPTATION_RULES提案已撤回，未接入源码。候选测试通过不等于线上质量通过；已有fixture仅作业务样例。

## 5. 六个业务案例与交付

| 案例 | 检查重点 |
| --- | --- |
| 退出后继续 | 状态延续，不重新规划 |
| 已读完但不理解 | 完成与掌握分开 |
| 时间减少 | 调整符合约束 |
| 只讨论不修改 | 业务状态不变，对话仍可保存 |
| 取消候选 | 原有效状态保留 |
| 资料不足或任务不明 | 说明未知或澄清 |

离线测控制流，少量在线测接线，人工核对语义与证据。不要求固定工具轨迹。

交付：六例结果、简短报告、3—5分钟演示。修实际失败，不无限扩集。

## 6. 暂不优先

- 扩建存档、无目标RAG调参、全部聊天迁入LangGraph。
- 分类大全、固定策略表、独立建议Agent、每轮额外分类。
- 后台记忆服务、通用自主写状态、复杂多Agent。

RAG保留开关与基线，默认配置以config.py为准。测试通过不等于建议正确或学习效果提升。
